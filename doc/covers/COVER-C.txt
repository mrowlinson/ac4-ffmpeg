Subject: [PATCH 0/11] native AC-4 encoder

This series adds a native AC-4 audio encoder (48 kHz, stereo + 5.1).
No B dependency; B deferred. Bottom-up split: tables -> core ->
lavc wrapper -> docs -> tests -> SAMPLES-unset -> silent-fold docs
-> negatives gate -> fold8 pin -> DSI wire x2; every patch builds
standalone (OBJS added under the not-yet-defined CONFIG_AC4_ENCODER
guard until 03/11 flips the codec live). Revert order is reverse;
reverting 03/11 deactivates the codec.

S5FU fix note: uniform DIG_GAIN 3.0 decoded every stereo file exactly
3/2 (+3.52 dB) hot vs DEE at the same dialnorm (S5-FU REAL-BUG). DEE
stages stereo at x2.0 and 5.1 at x3.0, so 6 stereo spectral sites now
take ENC_CORE_DIG_GAIN_STEREO 2.0 while 6 MC sites keep 3.0 (all MC
parity byte-identical; spliced fixed frames decode within 0.04 dB of
DEE). This re-pin is the only byte change in 05/11.

Overflow guards: fuzzing found three s64 sites, all now safe.
Wrapper (03/11): crash-1 pts_base add saturates (av_sat_add64,
encodes rc 0), crash-3 top-500 bit_rate values take early EINVAL
(exit 234). Core (02/11): crash-2 LLONG_MAX iframe_interval step
rejected at init (-EINVAL, exit 234; LLONG_MAX-1 still encodes).
ASan/UBSan clean on all three inputs.

Why: completes the codec pair; Series E (TS mux) and D (MP4) both
need an encoder-sourced, sample_rate-carrying test source, and D
rides this series' DSI-extradata contract (raw DSI bytes as
extradata, packed per ETSI 103 190-2 E.5, empty = hard error).

Provenance: this AC-4 encoder is an independent cleanroom
implementation in C, written from the published ETSI specifications
TS 103 190-1 V1.4.1 and TS 103 190-2 V1.3.1 plus black-box behavioral
observation. No Dolby SDK, reference code, or disassembly was used in
the submitted code; numeric codebook/coefficient tables are
value-only transcriptions from the ETSI deliverables (generators and
source versions cited per table), and all comments are original prose
referencing the standards by table/clause number only. The CLI-parity
layer that reproduces the vendor tool's help/diagnostic text
byte-exact is intentionally excluded from this submission. Note AC-4
is covered by Dolby patents; this submission addresses copyright-clean
code only and implementers/distributors should consider patent
licensing.
