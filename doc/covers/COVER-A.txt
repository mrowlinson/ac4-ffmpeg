Subject: [PATCH 0/2] native AC-4 decoder for raw .ac4 streams

This series adds a native AC-4 audio decoder, wired to the raw .ac4
demuxer already upstream. Base is master 3e6cd5e; the series applies
and decodes standalone -- no earlier series required for decode. The
A0 carriage patch (codecpar + timestamps, posted separately) pairs
with it for stream copy and seekable pts, but decode-to-PCM is proven
on pristine master without it.

Patches:
  [PATCH 1/2] avcodec: add native AC-4 decoder core
    Decoder engine: bit reader, entropy, IMDCT, QMF, A-SPX, ACPL,
    loudness, channel/render logic, static tables (landing as
    *_tab.c/h: *_tables.c/h would match libavcodec's generated-tables
    CLEANFILES pattern and be deleted by `make clean`). No lavc API
    surface yet; in-tree port of the dec-lib snapshot (FFmpeg LGPL
    headers + CLI/shim strip, zero behavior edits). Builds inert
    under the not-yet-defined CONFIG_AC4_DECODER guard.
  [PATCH 2/2] avcodec: wire ff_ac4_decoder
    AVCodec wrapper: init/decode/flush/close, re-framed raw input,
    drain-per-feed to NEED_MORE, seek as close+reopen, process-wide
    lib serialization, S16-only v1, EXPERIMENTAL (decode needs
    -strict experimental). Truncated-tail rule: a lone unanchored
    framing fails loud at EOF (no-sync diagnostic, zero output).
    First patch exposing decoder behavior.

Why first: FFmpeg has no AC-4 decoder, and this series has zero
sample dependencies, so it can post without waiting on the samples
mail that gates the FATE-carrying patches (A0's folded M3 tests,
Series B). Minimal reviewable unit before docs/FATE (Series B) and
encoder (Series C) build on it.

Testing:
  ./ffmpeg -strict experimental -i clip.ac4 -map 0:a out.wav
  byte-exact vs the dec-lib oracle on stereo / 5.1 / 7.1 / IMS /
  all-gap vectors (11/11 cmp-identical); negative controls loud and
  terminating (mid-stream config change, garbage cap, no-bed,
  truncated tail); standalone --enable-decoder=ac4 build; ASan/UBSan
  clean on decode paths; patcheck clean-under-triage; full make
  green; `make clean` preserves all committed sources.

FATE: none in this series; decoder tests land in Series B (B2),
which posts only after the samples-request mail is confirmed and
`make fate-rsync` shows ac4/clip-* (+24 h clock). No suite files
needed for this series.

N5 note (rate labels, fix LANDED): the wrapper passes lib rate
labels straight through, now the FIXED output values -- output rate
= base_fs x sf_mult on all fri rows, each internal frame mapped to
Table-70 output counts (e.g. the gpac vector: 48000 Hz with
1601/1602-sample frames, 298 frames = 5727312 bytes; container and
lib timing agree at 48 kHz). The wrapper latches spf from the
get_info max and sizes each frame from its actual count. This series
pins no goldens; Series B FATE goldens are recorded against these
fixed labels.

Provenance: this AC-4 decoder is an independent cleanroom
implementation in C, written from the published ETSI specifications
TS 103 190-1 V1.4.1 and TS 103 190-2 V1.3.1 plus black-box behavioral
observation. No Dolby SDK, reference code, or disassembly was used in
the submitted code; numeric codebook/coefficient tables are
value-only transcriptions from the ETSI deliverables (generators and
source versions cited per table), and all comments are original prose
referencing the standards by table/clause number only. Note AC-4 is
covered by Dolby patents; this submission addresses copyright-clean
code only and implementers/distributors should consider patent
licensing.
