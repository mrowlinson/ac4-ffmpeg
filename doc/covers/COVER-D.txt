Subject: [PATCH 0/6] MP4 ac-4+dac4 support + AC-4 parser

Last series of the stack (A0 -> A -> B -> C -> E -> D, plain `git am`
on 3e6cd5e): MP4 carriage for AC-4 plus the frame parser both
carriages need. Stack parent: C + E (needs the encoder
DSI-extradata contract: raw DSI bytes as extradata, packed per ETSI
103 190-2 E.5, empty = hard error; and 6/6 asserts Series E's
0x7F/0x15 descriptor bytes). Order inside the series is
parser-first: MP4 demux sets need_parsing = HEADERS, which is dead
without a registered parser, and the TS demux tags already in-tree
need only the splitter.

Patches:
  [PATCH 1/6] avcodec: add ff_ac4_parser
    ParseContext + combine_frame split loop (AC40/41 sync scan,
    ext-len, AC41 CRC-16, chain-anchor + TOC-head gate, 1-byte

    head+bed walk (bail-untouched); output-domain duration/rate

Deferred by design: the parser lands on the new header-only
libavcodec/ac4_toc.h (one walker, one rate table); the raw demuxer
converges onto it in a follow-up once its goldens re-pin to parser
keyflags. The mux strip stays a local framing parse (aacdec.c
precedent); MP4 demux keeps dac4
opaque (AAC-esds model); TS param-fill FATE rides a Series-E
follow-up. Feed-shape contract decided: demuxers/muxers emit bare or
shape-preserved frames, the decoder sniffs the first 2 bytes.
